# Refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Зніми стан «до»** і запиши числа дослівно. Кожну команду запускай окремо,
   не через `&&`: падіння однієї не має ховати результат решти.
   ```bash
   cd app
   npm run check:rules   # запиши рядок цього файлу в `by file` і загальний TOTAL
   npm test              # запиши кількість тестів і файлів
   npm run typecheck     # запиши: чисто / список помилок
   ```
   Усі три статуси потрібні окремо — інакше «до» і «після» не порівняти.
2. Прочитай цільовий файл і його тест поруч (`<ім'я>.test.ts`). Тест — це
   специфікація поведінки: URL, тіло запиту, тексти помилок.
3. Випиши список порушень саме цього файлу з виводу `check:rules` (рядок і
   правило). Виправляй рівно їх, за правилом `conventions` з `.claude/rules/`.
4. Заміни роби точково: `fetch` → `postJson`, `process.env` → `readEnv`,
   `JSON.parse` → `parseJson` + guard, `console.*` → `log`, `any` → `unknown` +
   guard. Сигнатуру експорту й форму запиту не змінюй.
5. **Зніми стан «після»** тими самими трьома командами, так само окремо, і
   порівняй усі три статуси з «до».

## Acceptance criteria

- [ ] `check:rules` для цього файлу: порушень стало менше, у жодного іншого файлу
      не побільшало; `TOTAL` знизився.
- [ ] `cd app && npm test` зелений, тестів не менше, ніж було; **жоден асерт і
      жодна фікстура не змінені**.
- [ ] `npm run typecheck` без помилок.
- [ ] Поведінка та сама: URL, тіло запиту й тексти помилок збігаються з тим, що
      стверджують наявні тести.
- [ ] Змінено рівно один файл — цільовий. Його імпорти читаються, але не правляться.

## Stop

- Лише вказаний файл. Інші файли — тільки читати.
- Якщо щоб позбутись порушення треба змінити `app/src/core/**` або будь-який інший
  захищений шлях — зупинись і дай звіт за правилом `do-not-touch`.
- Якщо тест падає через те, що конвенція змінює зовнішню поведінку, — **не чіпай
  тест**: зупинись, покажи діф і поясни розбіжність.
- У підсумку покажи таблицю «до → після» для всіх трьох: `check:rules`, `npm test`
  і `npm run typecheck`.
