## Ядро (`src/core/`) — захищена зона

`core/` належить платформній команді: той самий core працює в усіх клієнтських
воркерах агенції. Зміни в ньому йдуть окремим PR через рев'ю цієї команди, тому
**у звичайних задачах `src/core/**` не редагується взагалі** — ні «дрібний фікс»,
ні «додам один тип». Якщо задача без цього не робиться, треба зупинитись і
описати, що саме потрібно змінити в core і навіщо.

Публічний API ядра — рівно ось це. Іншого не існує, і вигадувати його не можна:

| Модуль | Експорт | Для чого |
|---|---|---|
| `core/types.ts` | `Lead`, `Result<T>`, `Integration` | спільні типи й контракт інтеграції |
| `core/http.ts` | `postJson(url, body, options?)` → `Promise<Result<string>>`, `PostOptions` | будь-який вихідний HTTP: таймаут, повтори на 5xx/429 |
| `core/config.ts` | `readEnv(name)` → `Result<string>` | читання змінних середовища |
| `core/parse.ts` | `parseJson(text, guard, label?)` → `Result<T>`, `Guard<T>`, `isRecord`, `isString`, `isNumber` | перетворення зовнішнього тексту на дані |
| `core/log.ts` | `log.info`, `log.warn`, `log.error`, `redact(text)` | журнал із маскуванням секретів |

Так само не редагуються: `app/scripts/**` (перевірка правил), `materials/**`,
`.coderabbit.yaml`, `.github/**`.

## Конвенції коду

1. **Помилки — це значення.** Функції, що можуть не вдатися, повертають `Result<T>`.
   Інтеграція не кидає винятків назовні: `send()` завжди повертає `Result<void>`.
2. **HTTP — лише через `postJson()`.** Прямого `fetch` в інтеграціях немає: у ньому
   нема таймауту, повторів і маскування URL у журналі. Нових HTTP-клієнтів (axios,
   got, ky) не додаємо.
3. **Змінні середовища — лише через `readEnv()`.** `process.env` поза `core/config.ts`
   не читаємо. Значення секретів не пишемо в журнал і не вшиваємо в код, навіть
   «тимчасово».
4. **Зовнішнім даним не довіряємо.** Будь-який JSON — відповідь API, тіло вебхука,
   файл стану — розбирається лише через `parseJson(text, guard)` з guard на
   очікувану форму. Невалідний JSON або неочікувана форма — це помилка
   (`Result` з `ok: false`), яку видно в журналі. Тихо підставити «значення за
   замовчуванням» і працювати далі — не можна: так пошкоджені дані стають
   непомітними, а наслідки — дорогими.
5. **Журнал — лише через `log`.** `console.*` поза `core/log.ts` не використовуємо:
   `log` маскує токени, а `console.log` друкує їх як є.
6. **Без `any`.** Для невідомих даних — `unknown` плюс guard.
7. **Без нових залежностей.** У застосунку нуль runtime-залежностей, і так має
   лишитись. Потрібна бібліотека — спершу питання в PR, а не `npm install`.
8. **Мінімізація даних.** У сповіщення (Slack, месенджери) не передаємо email і
   телефон ліда — лише ім'я, джерело й бюджет. Повні дані йдуть тільки в системи
   обліку (таблиця, CRM).
9. **Імена.** Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу.

import { log } from "../core/log.js";
import type { Integration, Lead } from "../core/types.js";
import { loadState, saveState } from "./state.js";

export interface SyncReport {
  pending: number;
  delivered: number;
  failed: number;
}

export async function runSync(
  leads: readonly Lead[],
  integrations: readonly Integration[],
  statePath: string,
): Promise<SyncReport> {
  const state = loadState(statePath);
  saveState(statePath, state); // створює файл стану при першому запуску

  const pending = leads.filter((lead) => lead.createdAt > state.lastSyncedAt);
  let delivered = 0;
  let failed = 0;

  for (const lead of pending) {
    for (const integration of integrations) {
      const result = await integration.send(lead);
      if (result.ok) delivered++;
      else failed++;
    }
  }

  const newest = pending.reduce(
    (latest, lead) => (lead.createdAt > latest ? lead.createdAt : latest),
    state.lastSyncedAt,
  );
  saveState(statePath, { lastSyncedAt: newest });
  log.info(`sync: ${pending.length} pending leads, ${delivered} delivered, ${failed} failed`);
  return { pending: pending.length, delivered, failed };
}

}

## Чому зупинився

Тип `Lead` оголошено в `app/src/core/types.ts`. За `materials/architecture-brief.md` `src/core/**` у звичайних задачах не редагують взагалі, навіть щоб «додати один тип». Його змінює платформна команда окремим PR, бо цей core спільний для всіх клієнтських воркерів. Якщо задача без цього не робиться, записка вимагає зупинитись і описати, що треба змінити. Без поля в `Lead` інтеграція `sheets-append` не може типобезпечно прочитати кампанію.

Обхідні шляхи я відкинув:
- **Локальний тип** на кшталт `Lead & { utmCampaign?: string }` в інтеграції. Він підмінює спільний контракт `Integration.send(lead: Lead)` у межах одного модуля.
- **Читати `utmCampaign` з об'єкта під час виконання** через `"utmCampaign" in lead`. Нормалізатор, який будує `Lead` з форми, швидше за все відкидає невідомі поля. Тоді в колонці завжди був би порожній рядок, і ніхто б не помітив, що даних немає. Записка прямо забороняє такі тихі значення за замовчуванням.

## Що потрібно змінити в core (запит до платформної команди)

// app/src/core/types.ts, interface Lead
  budgetUsd?: number;
  /** utm_campaign із форми сайту; відсутнє, якщо форма його не передала. */

  createdAt: string;

Поле необов'язкове, тож нічого з наявного коду не зламається. Після зміни треба перегенерувати `scripts/core.lock.json`, і це теж робить платформна команда.

## Що я зроблю, коли поле з'явиться в `Lead`

1. **`sheets-append.ts`:** кампанія піде в кінець рядка:
   `[lead.createdAt, lead.name, lead.email, lead.phone ?? "", lead.source, lead.utmCampaign ?? ""]`. Порожній рядок за відсутності значення працює так само, як для `phone`. Порядок наявних колонок не зміниться.
2. **`sheets-append.test.ts`:**
   - у наявному тесті на успішну відправку очікуваний рядок отримає `""` в кінці;
   - новий тест на лід з `utmCampaign: "autumn_sale_2026"` перевірить, що кампанія стоїть в останній колонці.
3. **Slack і Telegram:** не чіпаю. За правилом мінімізації даних у сповіщення йдуть лише ім'я, джерело й бюджет.

Ще дві речі поза кодом:
- Коду, який перетворює заявку з форми на `Lead`, у цьому репозиторії немає: `runSync` отримує вже готові ліди. Того, хто відповідає за цей код, треба попросити перекладати `utmCampaign` з форми в `Lead`, інакше колонка буде порожньою.
- У самій Google-таблиці треба додати заголовок нової колонки в кінці.

Як рухаємось далі? Можу оформити зміну в core як окремий PR чи issue для платформної команди. Або, якщо вони вже погодили поле, одразу внесу зміни в `sheets-append` і тести.
